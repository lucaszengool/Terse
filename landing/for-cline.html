Frequently Asked Questions

Everything about using Terse with Cline.

How does Terse detect Cline?
Via process and configuration detection — no plugins or Cline settings changes. Detected sessions appear in the agent monitor with token usage, estimated per-turn cost, burn rate, and session history.
Why does Cline use so many tokens?
Every autonomous turn re-sends instructions, file context, and history — and tool loops multiply it. Terse compresses your prompts 40–70% and its circuit breaker stops a looping session before the next API call.
Can I set a spending limit for Cline?
Yes. Set a burn-rate, token, or dollar ceiling in the budget circuit breaker. On breach, Terse escalates alert → SIGSTOP pause → SIGTERM kill, enforced before the next API call, with one-click resume.
Is Cline monitoring as deep as Claude Code?
No — Claude Code gets exact tokens, cache efficiency, and 30-day backfill via JSONL streaming. Cline gets process/config detection with session-level stats and estimates. Optimizer, Doctor, and breaker work fully for both.
Does Terse compress prompts I type into Cline?
Yes — the 35+ technique pipeline runs in Light, Balanced, or Aggressive mode on the text you type, with code blocks, paths, and identifiers always protected. Typical reduction is 40–70%.
Does any Cline data leave my machine?
No. Detection, monitoring, compression, and budget enforcement all run on-device on macOS or Windows.

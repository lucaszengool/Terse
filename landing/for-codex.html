Frequently Asked Questions

Everything about using Terse with the OpenAI Codex CLI.

How does Terse detect OpenAI Codex?
Via process and configuration detection — one of 8 agents recognized out of the box, no Codex config changes. Sessions appear in the monitor with token usage, estimated cost, burn rate, and history.
Can I set a spending limit for Codex?
Yes. Set a burn-rate, token, or dollar ceiling. Because Codex is a local CLI process, Terse enforces directly: alert → SIGSTOP pause → SIGTERM kill, before the next API call, with one-click resume.
Does Terse compress the prompts I give Codex?
Yes — the 35+ technique pipeline runs in Light, Balanced, or Aggressive mode. Code blocks, shell commands, file paths, and identifiers are always protected. Typical reduction is 40–70%.
Can Terse stop a looping Codex agent?
Yes. A loop shows up as a burn-rate spike within minutes. With a ceiling armed, Terse alerts and then pauses the process before its next API call — a loop that would have run all night stops at your limit.
Is Codex monitoring as deep as Claude Code?
No — Claude Code gets exact tokens, cache efficiency, and 30-day backfill via JSONL streaming. Codex gets process/config detection with session-level stats and estimates. Optimizer, Doctor, and breaker work fully for both.
Does any Codex data leave my machine?
No. Detection, monitoring, compression, and budget enforcement all run on-device on macOS or Windows.
